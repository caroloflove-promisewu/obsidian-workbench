# Personal Workbench · Obsidian 插件

移动端优先的个人工作台，**直接读写本地库，零后端**。四大端（iPhone / iPad / Windows 桌面 / Windows 笔记本）通过坚果云同步同一份 vault，天然一致。

当前版本 **0.4.12**。

## 快速记录（0.3.0 回归网页版模型）

**一条笔记 = 一个独立文件**，不是往当天文件里追加。文件名 `YYYYMMDDHHmm｜标题｜关键词.md`，
存在暂存筐目录下，内容套用「卡片盒 · 信息卡」模板：

```markdown
- 正文写在这里

#### 关联思考：
- **链接到：** 
- **引出问题：**
- **可行的行动：**
- **潜在思考主题：**
```

首页输入区：**内容** + **标题 T / 关键词 K**（常显）+ **关联思考三项**（可折叠），
外加「仅新建空白卡」按钮。同时间戳重名自动追加 `-2` `-3`，绝不覆盖。

- 模板可自定义：设置里填「快速记录模板」路径，或点「把内置信息卡模板写入库」生成一份再改
- 标题/关键词留空时，文件名保留字面字母 `T` / `K`（方便日后回补）
- 旧版按天追加的 `02暂存筐/<日期>.md` 文件仍原样保留，只是不再新增

## 界面风格

界面沿用早期**网页版工作台的浅色 App 观感**：浅灰底 + 白色圆角卡片 + 极轻阴影 + 蓝色主按钮 + 行列表式清单项。
实现方式是在 `styles.css` 里把 Obsidian 主题变量**重定向**到工作台自己的色板，因此：

- **浅色 / 深色两套配色**，跟随 Obsidian 的 `.theme-light` / `.theme-dark` 自动切换
- 换肤不依赖逐条改样式，将来想还原成「完全跟随 Obsidian 主题」，删掉两个 `.theme-* .wb-root` 变量块即可
- 色值取自 Apple 系统色板（`#f5f5f7` / `#ffffff` / `#0a84ff` / `#34c759` / `#ff9500` / `#ff3b30`）

> 近半年热力图折叠在打卡模块末尾（标题右侧「热力图 ▸」），默认收起 —— 首页仍然克制，但什么都不缺。

### 番茄钟（0.3.0 新增）

- **自定义时长**：预设 15 / 25 / 45 / 60 分钟，也能手填 1–180 任意整数（`设定` 按钮或回车）
- **专注 → 休息自动衔接**，完成后进入 5 分钟休息（时长可在设置里改）
- **暂停 / 继续 / 重置**；专注中改时长不会打断当前这一轮
- 表盘进度环实时反映剩余比例，专注（蓝）/ 暂停（橙）/ 休息（绿）三态换色
- 完成后可选**写一条记录进今日日程**（`🍅 专注 N 分钟`，`due::` 为今天），
  默认开启，可在卡片上或设置里关掉

> 计时状态**刻意不落盘**：关掉工作台/重开卡片会回到待机，不会"偷跑"。
> 完成记录才落盘，且写进**今天**的日程段（不是收件箱）——所以它天然能进你已有的日程与统计体系，不新增数据格式。

## 项目笔记与待办（0.4.0）

项目卡片现在是两层：**待办** + **项目笔记**。原来的「成果要求」和「节点」都去掉了。

### 待办 = 待办 + 日期

一条待办就是一行 Markdown，日期直接写在行尾：

```markdown
## 待办
- [ ] 收集竞品资料
- [ ] 定下包装方案 📅 2026-12-20
- [x] 立项评审 📅 2026-08-01
```

- **有日期** → 往日程写一条 `项目名·待办`，日期为那天；改日期是更新同一条，不是新增
- **没日期** → 只留在项目里，不进日程。想把无日期的挪进日程，点日期胶囊补一个就行
- 日期胶囊**过期变红、今天蓝色、未来灰色**；已完成的不标红
- 打卡卡片上的「已排期 N」= 带日期且未完成的条数

> 老版本的 `里程碑:` frontmatter 会在启动时**自动迁移成带日期的待办**（同名待办已存在就跳过，可重复执行）。

### 项目笔记：折叠只看标题，点一下跳正文

格式固定为三级标题 + 时间戳，最新的一条在最上面：

```markdown
## 项目笔记
### 2026-10-19 10:32 · 和供应商敲定打样时间
对方答应周四出样，先做 3 版手感对比。
另外确认了起订量 500 起。

### 2026-10-12 15:08 · 竞品价格带梳理
主流区间集中在 89–129 元。
```

- **时间戳自动写**（`YYYY-MM-DD HH:mm`，本地时区），**关键词标题你手写**
- **折叠时只显示「时间戳 · 标题」一行**，展开才显示正文摘要（每条最多 120 字，超出省略）
- **点任意一条** → 在 Obsidian 里打开这个项目的 md 文件，**滚动到那一段并定位**（行号换算已算上 frontmatter）
- 「＋ 记一条」弹窗里标题回车就能跳到正文，正文是多行文本框，换行原样保留
- **弹窗是大的**（0.4.7）：桌面 92vw × 88vh，手机上铺满全屏，正文框吃掉剩余高度；「编辑笔记」同样尺寸
- **在 md 里手写一条也能显示**（0.4.7）：格式照上面写，切回工作台就自动出现，不用重开插件
- 笔记全存在项目 md 文件里，没有额外数据文件；手机上也能直接看

## 可视化

- **习惯热力图**：26 周 × 7 天，每天打卡的习惯数映射到 5 档色阶（**首页打卡模块底部，默认折叠**）
- **首页打卡行**：每习惯最近 7 天格子 + 一键打卡 + 连续天数 + 「⋯」改名/补卡/撤销/删除
- **项目进度条**：按待办完成率计算；无待办时按状态粗估（项目页）

## 安装到 vault

把 `manifest.json`、`main.js`、`styles.css` 三个文件放进：

```
<你的库>/.obsidian/plugins/obsidian-workbench/
```

然后在 Obsidian「设置 → 第三方插件」里启用。

## 手机速记（无需后端）

插件注册了自定义协议 `obsidian://workbench`：

```
obsidian://workbench?action=addNote&text=买牛奶&title=采购&keyword=生活
obsidian://workbench?action=addNote&text=想法&question=为什么&actionItem=先试一版
obsidian://workbench?action=addTodo&text=写第二章&project=07工作台/03项目/年终总结.md
obsidian://workbench?action=addSchedule&text=交报告&date=2026-03-10
obsidian://workbench?action=open&tab=projects
```

`addNote` 支持的参数与首页四组输入框一一对应：`text`（正文）/ `title`（T）/ `keyword`（K）/ `question`（引出问题）/ `actionItem`（可行的行动）/ `theme`（潜在思考主题）/ `stamp`（自定义时间戳，默认取当前时刻）。

设置面板里这四条链接**点一下就能复制**，直接粘进 iOS 快捷指令。

兜底（不依赖插件）：`obsidian://new?file=02暂存筐/速记&content=...&append=true`

## 数据约定

默认目录（**0.3.1 起**，均可在设置里改）：

| 用途 | 默认路径 |
|---|---|
| 项目卡片 | `07工作台/03项目/` |
| 日程、习惯打卡、清单 | `07工作台/04打卡/` |
| 快速记录暂存筐 | `02暂存筐/`（仍在库根，未收进 `07工作台`） |

> 从 0.3.0 及更早升级时，若你**没有手动改过**这两个目录，插件会自动把 `03项目` / `04打卡` 迁移到 `07工作台/` 下；**自己改过路径的不会被覆盖**。

- 日程存**单文件** `<打卡目录>/日程.md`，按 `## YYYY-MM-DD` 分段
- 条目用行内字段：`due::` / `time::` / `repeat::` / `id::` / `source::` / `done::`
- 重复条目完成状态按日期存（`done::2026-03-04,2026-03-11`）
- 项目 = `<项目目录>/*.md`，frontmatter 存状态，正文 `## 待办`（行尾 `📅 YYYY-MM-DD` 表示计划日期）+ `## 项目笔记`（`### YYYY-MM-DD HH:mm · 标题` 分段）
- 习惯 = `<打卡目录>/习惯打卡.md`，`## 习惯名` 段下 `- YYYY-MM-DD` 即打卡记录
- 清单 = 任意 md 文件，`##`~`####` 分节即模块，`- [ ] 条目` / `- [x] 已完成`；**清单页「＋」新建的清单会建在打卡目录下**，写好 `# 名称` + `## 未分类`，并登记进设置的清单列表
- **日期一律本地时区**，绝不用 `toISOString()`

### 插件与编辑器可以同时改同一个文件（0.4.7）

项目笔记、清单、日程都是普通 md，你既能在工作台里改，也能在 Obsidian 编辑器里直接改 ——
两边不会打架：插件自己写文件时会先打「自写标记」，写完之后到达的那次 `modify` 事件被吃掉，
所以只有**真的来自外部**的改动才会被记下来。改了之后不需要手动刷新，切回工作台
（窗口重新获得焦点 / 页面重新可见）就会自动重绘；一直开着不动的话，还有 15 秒兜底轮询。

- **0.4.12（GPT 复核低优先级项 T2–T8 收尾）** — 复核报告剩下的五条逐条核对，该修的修、该钉测试的钉测试：
  - **T5 · 多设备同时改同一个文件（本轮唯一动代码的一条）**。四台设备经坚果云同步同一份库，插件不做冲突合并；`withLines`（清单编辑）和 `setScheduleDone`（日程勾选）都是「读 → 改 → 整文件覆盖写回」，读和写之间另一台设备落了盘，对方的改动就被抹掉。**最小改法：写前重读一次，发现内容变了就在新内容上把这次编辑重算一遍**（冲突自愈一拍）。不能根除冲突（Obsidian 不提供原子写），但能把最常见的「同步延迟一拍」救回来。清单侧新增 3 条测试、日程侧 2 条，都用「第一次 read 给旧内容、之后给新内容」模拟同步竞争。
  - **T4 追问 · 月末对齐的勾选记录**。每月 31 号的任务在 2 月落在 2/28，勾选记进 `done::` 的是**对齐后的 2027-02-28**；3 月照常按 3/31 判定、不受 2 月那次影响。新增 5 条测试把这个口径钉死。
  - **T3 · 清单精确行编辑的组合场景**。补一条「删一条 → 加一条 → 改名」的连贯测试：行号随操作变化，每一步都按**最新解析**定位，最后断言行数不变、新条目落在正确二级模块内、公众号链接和账号行原位不动。

- **0.4.11（GPT 交叉复核后修的三条）** — 三条都来自复核报告，我逐条核实成立才动手。三条共性是**同一个概念在两处各写一遍，然后分叉了**：
  - **P0 · 列表视图的重复日程「勾了不生效」**（T1③）。`renderList()` 给所有条目无条件写 `showDate: it.date` / `showDone: it.done`；对重复条目来说 `date` 是**规则起点**、`done` 恒 false。于是在列表里勾一条每周任务，`done::` 被记到规则起点那天，界面按「该做那天」去读又读不到。**这跟 0.4.10 修的首页那条是同一个根因**，只是漏了这个视图。
    - 新增 `currentDueDay(item, t)`：给出「现在该做的那一次」。口径按你拍板的来 —— **向前看本次该做的，含已逾期未做的那次，但只看「最近一次」不往回翻老账**。
    - 「不看老账」是有意的：用户开始用插件之前那些日子根本没发生，一路追下去等于拿一个他从没承诺过的义务天天催他。
    - 列表分组随之改为按「该做那天」分组（标题是日期而不是「重复任务」），逾期那次的标签标红，并额外显示一行淡色的 `起点 YYYY-MM-DD`，免得用户以为「我明明设的每周三，怎么写成 10 月 22 日」。
    - 起点在未来的重复任务（规则还没开始）单独归到「未开始」小节，**不给勾选框**，只能删。
  - **P0 · 目录失效被当成「空目录」**（T6）。`resolveDir()` 找不到目录时和「目录在、只是空的」返回一模一样，页面就渲染成「这个目录里还没有项目」——数据其实还在库里，只是插件迷路了，但用户看到的是「我的东西全没了」。
    - `resolveDir()` 新增 `missing` 状态，`healDirs()` 单独交出 `missing` 键名。
    - **真正拦住写入的是 `vault.ts`**：落在失效目录下的 `writeFile` / `appendFile` 直接抛错。因为 `writeFile` 会自动 `ensureFolder` 逐层建目录 —— 一旦失效，用户点一下「新建项目」就在旧路径下长出一个空目录，比单纯看不到更让人以为数据丢了。
    - 界面：新增 `.wb-alerts` 提示区，红边、写明失效路径、写明「已暂停写入」，带「去设置改目录」和「重新检查」两个按钮。**每个页面只报跟自己相关的目录**（项目页不拿打卡目录的坏消息烦人）。
    - 设置页也有同样的提示块；改完路径立刻重判，好了自动消失。
  - **P1 · 清单重命名吞掉行尾字段**（T4）。`renameItem` 的注释写着「保留 `stage::` 这类行尾字段」，代码却是 `lines[line] = m[1] + next` —— 直接丢掉。
    - 新增 `splitTail(text)`：只认三种尾巴 `key::value` / `#标签` / `^block-id`，从行尾往前连续剥，遇普通文字即停。
    - **不误伤正文**是重点：`📅 2026-10-25`、URL、`账号：xxx`、`14:30`、`买牛奶 2 盒` 全部整体保留（有 8 条边界测试盯着）。
    - 用户自己在改名时写了新字段，就以用户写的为准，不重复追加旧尾巴。
  - **同时修掉的一条自己引入的缺陷**：失效目录状态一开始写成了模块级 `Set`，那是**全进程共享**的 —— 同一个进程里两个插件实例/两个库会互相污染，A 库标失效会拦掉 B 库的写入，而且没人来解封。改成按 `app` 隔离（`WeakMap`）。加了反向验证：B 库不受 A 库影响。
  - **重绘入口统一收口**：以前 `isEditing()` 只挡住 `refreshIfDirty()`，`switchTab()` 和 `main.ts` 的 `refreshViews()` 都是无条件 `render()`。你在输入框打半句话、随手点一下标签栏，整块 DOM 重建，没保存的文字就没了。现在全部走 `view.requestRender()`：**没在打字立刻重绘，正在打字就挂起，失焦后自动补上**（挂起 ≠ 丢掉这次刷新）。
